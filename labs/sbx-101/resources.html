Docker Sandboxes — quick reference

The commands this lab teaches, and where to go next.

Install

macOSbrew install docker/tap/sbx
Windowswinget install -h Docker.sbx
RequiresDocker Desktop 4.58+ · written against sbx v0.35

Sandboxes

sbx create --name <n> claude <dir>Create a sandbox for a workspace
sbx run --name <n>Attach to the agent (restarts a stopped sandbox)
sbx run claudeOne step: create + attach with a default name
sbx ls · sbx stop · sbx rmList, halt, delete (rm confirms; refuses while in use)
sbx resetWipe everything: sandboxes, policies, secrets, sign-in

Network policy

sbx policy resetPick Open / Balanced / Locked Down
sbx policy lsPolicies and rule summaries
sbx policy allow|deny network <host>Rules; wildcards *.host.com, **, ports, --sandbox scoping
sbx policy rm network --resource <host>Remove a rule
sbx policy log <sandbox>The audit trail — the source of truth

Secrets & MCP

sbx secret set -g <service>Store a provider key in the OS keychain
export SBX_MCP_URL=… then restart daemonUnlocks the sbx mcp subtree (per shell!)
sbx mcp add|inspect|ls|loadRegister and manage MCP servers
sbx create … --static-mcp a --static-mcp bThe gateway is born at create time; load adds servers to an existing gateway (else: 409)
